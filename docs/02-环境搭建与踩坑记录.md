## 一、网络环境实测结论（重要）

在这台机器上用 `curl` / PowerShell 实测的结果：

| 目标 | HTTPS | HTTP(80) | 结论 |
|---|---|---|---|
| www.baidu.com | ✘ 000 | ✔ 200 | HTTPS 被拦截 |
| mirrors.aliyun.com | ✘ 000 | ✔ 200 | 只能走 HTTP |
| github.com | ✘ 超时 | ✘ | **完全不可达** |
| gitee.com | ✔ 200（**node 可访问**） | 301→https | 用 node 下 |
| gitcode.com / atomgit.com | ✔ 200 | — | 可用 |
| registry.npmmirror.com | ✔ 200 | — | 可用 |
| maven.aliyun.com | ✔ 200 | 301→https | 可用 |

**关键发现**：

1. `curl.exe`（走 Windows Schannel）**无法完成 TLS 握手**，所有 HTTPS 请求返回 `http=000`；
   但 `node`（自带 OpenSSL）**HTTPS 正常**。
   → 因此**统一用 Node 脚本下载**（`scripts/dl.mjs`），不要用 curl。
2. `npm.ps1` 受执行沙箱限制会失败（退出码 1 且无输出），
   如需用 npm，改用 `node "C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js" ...`。
3. `git clone https://gitee.com/...` 失败（git 用系统 TLS 栈），只能通过 node 抓 raw 文件。

## 三、踩坑记录（都踩过了，记下来省时间）

### 坑 1：config.ini 带 UTF-8 BOM 会被忽略
现象：明明写了 `secret=xxx`，调 API 却报 `-100 Incorrect secret`，且 config.ini 被改写。
原因：ZLMediaKit 的 ini 解析器不认识 BOM，把整个文件当空的，于是生成全套默认配置并回写。
解决：**写 config.ini 必须无 BOM**。

```powershell
# 正确写法
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))
# 验证前 3 字节不是 EF BB BF
$b = [System.IO.File]::ReadAllBytes($path); '{0:X2} {1:X2} {2:X2}' -f $b[0],$b[1],$b[2]
```

### 坑 2：ZLM 2024+ 的 api.secret 有格式要求
现象：日志 `The api.secret is invalid, modified it to: <随机串>, saved config file`，
每次启动 secret 都变，网关永远对不上。
原因：新版只接受 **32 位字母数字串**（如 `a8Fk3QzR7mWp2TvN6xLc9Yb4Hs1Jd5Eg`），
UUID 格式（带 `-`）非法。
解决：config.ini 与 `application.yml` 的 `vgw.zlm.secret` 使用同一个 32 位字母数字串。

### 坑 3：Windows 下正则替换要处理 `\r`
config.ini 是 CRLF 换行，PowerShell 里 `(?m)^key=0$` **匹配不到**（行尾有 `\r`）。
解决：写成 `(?m)^key=0\s*$`。

### 坑 4：live 流的 Range 请求不生效
`curl -r 0-511 http://127.0.0.1/live/cam01.live.flv` 会一直收数据直到超时。
验证 FLV 只需看前三字节是不是 `FLV` 即可，别指望它按 range 截断。
