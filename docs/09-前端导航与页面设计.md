# 前端导航与页面设计

> 菜单已确认（5 个一级菜单）。本文档定义每个页面的**字段、操作、接口对照、交互细节**，
> 开发时按此实现，验收时按此逐项核对。
> 技术方案：**Vue3 + Element Plus 本地静态化，无构建步骤**（避免 npm 构建链与内网依赖问题）。

---

## 一、导航结构（已确认）

```
视频数据网关
├─ 📊 概览
├─ 📹 视频资源
│    ├─ 设备管理
│    └─ 通道管理
├─ ▶️ 实时视频
├─ 📋 业务台账
│    ├─ 事件流水
│    └─ 流会话 / 录像
└─ 🔑 API 客户端
```

（可选，二期）`⚙️ 系统状态`：健康检查、ZLM 信息、接口文档与播放页入口。

---

## 二、技术方案

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3（global 版，非 SFC） | 无需构建工具 |
| UI 库 | Element Plus（full 版） | 表格/表单/弹窗开箱即用 |
| 路由 | 自实现的 hash 路由（`#/ledger`） | 免 vue-router 依赖 |
| 请求 | 原生 `fetch` 封装 | 免 axios 依赖 |
| 图表 | **不用**，改用数字卡片 | 省一个依赖，答辩够用 |
| 部署 | Spring Boot 静态资源目录（外部路径） | 改 HTML 刷新即生效，不用重新编译 |
| 依赖来源 | 本地 `web/vendor/`（从 npmmirror 下载） | 演示环境断网可用 |

### 鉴权方案（已定：方案 A）

进入系统时输入 `api-key`，存 `sessionStorage`，之后所有请求自动带 `api-key` 头。

```
首次访问 → 弹出"输入 API Key"对话框（默认提示：vwg_demo_app）
         → 调一次 /api/v1/health（放行接口）确认网关可达
         → 调一次 /api/v1/stats/overview 验证 key 有效
         → 存入 sessionStorage，进入系统
后续请求 → 统一在 fetch 封装里加 header
收到 401 → 清空 key，重新弹框
```

答辩话术：*"以 API 客户端凭证作为访问凭证，未引入用户体系 —— 因为本平台服务对象是业务系统而非个人。"*

## 三、逐页设计

### 3.1 📊 概览

**布局**：上方 4 个数字卡片（一行），下方"最近事件"表格（10 条）。

**卡片（4 个）**

| 卡片 | 取值 | 接口字段 |
|---|---|---|
| 在线通道 | 当前有流在推的通道数 | `channelOnline` |
| 进行中会话 | 正在推流的路数 | `runningSessions` |
| 今日推流次数 | 今天开始过多少路 | `todayPublishCount` |
| 今日被拒次数 | 今天有多少非法推流被拦 | `todayRejectCount` |

**下方表格**：最近 10 条台账（时间、事件类型、通道、来源、客户端、结果）

**接口**：`GET /api/v1/stats/overview`、`GET /api/v1/ledger?page=1&size=10`

**附加**：右上角显示 ZLM 状态徽标（`zlmAvailable` → 绿色"媒体服务器正常" / 红色"媒体服务器不可用"）

---

### 3.2 📹 视频资源 › 设备管理

**表格列**：`设备编码`、`设备名称`、`接入类型`、`厂商`、`IP`、`状态`（在线/离线 tag）、`启用`、`操作`

**操作**
- 右上：`+ 新增设备`
- 每行：`编辑`、`删除`

**新增/编辑弹窗字段**

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| 设备编码 | 输入框 | ✅ | 唯一，建后建议不改 |
| 设备名称 | 输入框 | ✅ | |
| 接入类型 | 下拉 | | RTMP / RTSP / GB28181 |
| 厂商 | 输入框 | | |
| IP 地址 | 输入框 | | |
| 启用 | 开关 | | 默认开 |
| 备注 | 输入框 | | |

**接口**：`GET/POST /api/v1/devices`、`PUT/DELETE /api/v1/devices/{id}`

**筛选**：关键字（设备名）、状态

---

### 3.3 📹 视频资源 › 通道管理 ★

**表格列**：`通道编码`、`通道名称`、`所属设备`、`流标识`（显示 `app/stream`）、`在线状态`、`启用`（开关，可原地切换）、`最近上线`、`操作`

**操作**
- 右上：`+ 新增通道`
- 每行：`编辑`、`删除`
- `启用` 列直接用开关切换（走 PUT）

**新增/编辑弹窗字段**

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| 所属设备 | 下拉（设备列表） | ✅ | |
| 通道编码 | 输入框 | ✅ | 唯一 |
| 通道名称 | 输入框 | ✅ | |
| stream_app | 输入框 | ✅ | 默认 `live` |
| stream_id | 输入框 | ✅ | **推流契约，建后不可改** |
| 拉流地址 | 输入框 | | `pull_url`，预留 |
| 启用 | 开关 | | 关掉后推流直接被拒 |

> 交互提醒：`stream_id` 编辑时置灰 + 提示"流标识与设备推流地址绑定，修改需设备端同步"。

**接口**：`GET/POST /api/v1/channels`、`PUT/DELETE /api/v1/channels/{id}`

---

### 3.4 ▶️ 实时视频

**布局**：在线流卡片墙（每路流一张卡片）

**卡片内容**：通道名、流标识、状态点（绿=在线）、观看人数、`▶ 播放` / `📷 截图`（截图本期不做）

**点击播放** → 弹出播放器弹窗（复用 `player.html` 的 flv.js 逻辑）：
- 调 `GET /api/v1/channels/{id}/play-address?protocol=flv` 拿地址
- 用 flv.js 播放，显示协议、延迟级别

**空状态**：`当前没有在线流` + 提示"先推流：`scripts\push-usb-camera.bat`"

**接口**：`GET /api/v1/streams`、`GET /api/v1/channels/{id}/play-address`

---

### 3.5 📋 业务台账 › 事件流水 ★核心

**筛选区**（一行）
- 通道（下拉，可空）
- 事件类型（下拉：全部 / 推流开始 / 推流结束 / 推流被拒 / 播放开始 / 播放结束 / 录像完成 / 接口调用）
- 时间范围（日期范围选择器）
- 客户端（下拉，可空）← **需后端补参数**
- `查询` / `重置`

**表格列**：`时间`、`事件类型`（彩色 tag）、`通道`、`客户端`、`来源`、`结果`、`详情`（点击展开 JSON）

**分页**：每页 10/20/50 可选

**空状态**：`暂无记录`

**接口**：`GET /api/v1/ledger?page&size&channelId&eventType&beginTime&endTime&clientId`

### 3.7 🔑 API 客户端 ★会上要求

**表格列**：`客户端名称`、`appKey`、`状态`（启用/停用 tag）、`失效时间`、`创建时间`、`操作`

**操作**
- 右上：`+ 创建客户端`
- 每行：`停用/启用`（切换）、`重置密钥`、`删除`

**创建弹窗**：输入 `客户端名称`、`备注`、`失效时间`（可选）
→ 提交后**弹出结果框，展示 `appKey` 和 `appSecret`**，大字提示：

> ⚠️ appSecret 仅此一次可见，请立即复制保存。关闭后将无法再次查看。

提供"复制"按钮。

**重置密钥**：二次确认后，同样弹框显示新密钥。

**接口**：`GET/POST /api/v1/api-clients`、`POST /{id}/enable`、`/disable`、`/reset`、`DELETE /{id}`

## 六、开发顺序与验收标准

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **1** | 静态资源接入 + 导航壳 + API Key 输入框 | 打开 `http://127.0.0.1:8088/` 看到左侧菜单，输入 key 后能进系统 |
| **2** | 概览页 | 4 个卡片有真实数字，下方最近事件有数据 |
| **3** | 业务台账（事件流水） | 能按通道/类型/时间筛选，分页正常 |
| **4** | API 客户端页 | 能创建并在弹窗看到密钥，能停用后立刻失效 |
| **5** | 设备/通道管理 | 能增删改，通道启用开关生效 |
| **6** | 实时视频 | 点卡片能弹出播放器并出画面 |
| **7** | 流会话/录像 Tab | 会话有时长，录像能点开回放 |

**每阶段完成即刷新浏览器验证**（前端改动不需要重新编译）。

## 七、交互约定

| 场景 | 约定 |
|---|---|
| 请求失败 | 顶部 `ElMessage.error` 提示，带 `msg` 与 `traceId` |
| 401 | 清空 key，重新弹输入框 |
| 空数据 | 表格下方显示 `暂无数据`，不要空白 |
| 时间显示 | 统一 `yyyy-MM-dd HH:mm:ss` |
| 危险操作 | 删除/重置密钥需二次确认 |
| 加载中 | 表格显示 loading |

## 八、明确不做（前端范围）

| 不做 | 理由 |
|---|---|
| 登录页 / 用户体系 | 用 API Key 代替，与后端鉴权模型一致 |
| 图表库（ECharts） | 用 4 个数字卡片替代，省依赖 |
| 响应式/移动端适配 | 演示在笔记本上进行 |
| 国际化 | 无需求 |
| 前端单元测试 | 三周项目，用可执行的验收清单替代 |
