## 明确不做的统一话术

| 不做 | 一句话理由 |
|---|---|
| **国标 GB28181 信令** | 信令层是独立大工程（注册/目录/INVITE/级联），三周做不深。媒体层已具备接收国标 PS 流的能力，信令对接列为二期。 |
| **用户/角色 RBAC** | 本平台的服务对象是**业务系统**而非人，因此用"API 客户端"而非"用户"做鉴权主体。 |
| **限流/配额** | 字段已预留（`rate_limit`），本期以台账记录调用量为主，限流作为可插拔能力留待开启。 |
| **多 ZLM 节点集群** | 单机场景够用；架构图与配置已预留 `mediaServerId` 扩展点。 |
| **录像计划/云录像/回放/PTZ/报警** | 属安防业务的纵深功能，非"数据网关"核心职责。 |

## 假设现在只有 3 天，砍到哪算哪的顺序

```
第1刀（必保）：C1 推流准入 → D1 D2 台账 → E1 接口 → F1 台账页
第2刀：C4 播放签名 → C5 C6 API客户端（已完成，不回退）
第3刀：E4 出口Webhook → C2 采集策略
第4刀：A3 拉流 → F2 F3 页面
第5刀：全部 P2
```

> 原则：**闭环优先**。宁可"推流→台账→接口→页面"这条线完整，也不要做四个半成品。
