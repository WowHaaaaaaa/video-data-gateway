## 0. 开讲之前：三件必须先搞清楚的事

### 0.1 地址用哪个

| 从哪发起 | 该用哪个 host | 说明 |
|---|---|---|
| **本机**（平台所在这台电脑） | `127.0.0.1` 或 `10.7.25.138` 都行 | 127.0.0.1 最短，推荐 |
| **局域网其他设备** | **`10.7.25.138`**（本机内网 IP） | 填 127.0.0.1 会指向**它自己**，永远推不上来 |
| 平台签发给别人的播放地址 | 目前是 `127.0.0.1`（配置项 `vgw.zlm.base-url`） | 要让别人能播，需改成 `http://10.7.25.138` |

> 本机 IP 查法：`ipconfig` → WLAN 的 IPv4 地址。当前是 **10.7.25.138**。

### 0.2 端口与协议

| 用途 | 地址 |
|---|---|
| **推流**（RTMP） | `rtmp://<host>/live/<streamId>`（端口 1935，可省略） |
| **拉流**（RTSP 出口/入口） | `rtsp://<host>:554/live/<streamId>` |
| 播放 · HTTP-FLV | `http://<host>/live/<streamId>.live.flv` |
| 播放 · HLS | `http://<host>/live/<streamId>/hls.m3u8` |
| ZLM 自带播放页 | `http://<host>/player.html` |
| 平台界面 / 接口文档 | `http://<host>:8088/` 、`http://<host>:8088/doc.html` |

### 0.3 **通道必须先登记**（这一步最容易漏）

平台的 `on_publish` 是一道闸门：**没登记过的流一律拒绝**。

```
设备推 live/dev1  →  on_publish 回调网关  →  查通道表
                                          ├─ 有且 enabled=1 → 放行，开流会话 + 台账 PUBLISH_START
                                          └─ 没有/已停用   → 回 {"code":-1} → 设备被断，台账 PUBLISH_REJECT
```

拒绝时设备侧看到的是：

```
Server error: [auth failed]: code:-1 msg:"stream not registered: live/dev1"
```

**所以顺序永远是：先在平台建通道 → 再去推流。**

建通道的 5 个关键字段（`通道管理 → 新增通道`）：

| 字段 | 值 | 说明 |
|---|---|---|
| 所属设备 | 随便选（建议给外部设备单独建一台） | 设备状态是派生的 |
| 通道编码 | `CH-TEST` | 唯一 |
| 通道名称 | `测试通道` | |
| app | `live` | 推流地址里的第一段 |
| stream_id | `dev1` | 推流地址里的第二段 |
| 接入方式 | **推流（设备主动推）** | 选了推流就不用填拉流地址 |
| 启用 | 开 | 关掉后该路推流会被拒 |

## 一、本机推流（推给本机的 ZLM）

### 1.1 三种视频源，四条命令

| 想推什么 | 现成脚本 | 等价的 ffmpeg 命令 |
|---|---|---|
| **测试画面**（彩条+计时，不需要硬件） | `scripts\push-test.bat` | 见下 A |
| **笔记本内置摄像头** | `scripts\push-builtin-camera.bat` | 见下 B |
| **USB 摄像头 / 任意采集设备** | `scripts\push-camera.bat "USB Video Device"` | 见下 B |
| **整块屏幕** | `scripts\push-screen.bat` | 见下 C |

**脚本参数速查**

```bat
scripts\push-test.bat                       :: 默认推 live/fakesrc（彩条+正弦音），一直推
scripts\push-test.bat 30                    :: 第 1 个参数是流 id！想限时要写全：push-test.bat fakesrc 30
scripts\push-test.bat dev1                  :: 推到 live/dev1
scripts\push-builtin-camera.bat             :: 默认 live/incam
scripts\push-builtin-camera.bat mytest      :: 换流 id
scripts\push-camera.bat "USB Video Device" dev1        :: 指定设备 + 流 id
scripts\push-screen.bat screencast 10 1280  :: 屏幕捕获，10fps，宽 1280
```

**A. 测试画面（最常用，用来验证链路）**

```bat
ffmpeg -re -f lavfi -i "testsrc2=size=1280x720:rate=25" ^
  -f lavfi -i "sine=frequency=440:sample_rate=44100" ^
  -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p -g 25 ^
  -c:a aac -b:a 64k -ar 44100 ^
  -f flv rtmp://127.0.0.1/live/dev1
```

**B. 真实摄像头（Windows / DirectShow）**

```bat
:: 先查设备名（把输出里的 name 或 Alternative name 抄出来）
ffmpeg -list_devices true -f dshow -i dummy

ffmpeg -f dshow -i "video=USB Video Device" ^
  -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p -g 25 ^
  -f flv rtmp://127.0.0.1/live/dev1
```

**C. 屏幕捕获（gdigrab）**

```bat
ffmpeg -f gdigrab -framerate 15 -i desktop ^
  -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p -g 15 ^
  -rtbufsize 100M -f flv rtmp://127.0.0.1/live/dev1
```

### 1.2 关键参数为什么必须有

| 参数 | 作用 | 不加会怎样 |
|---|---|---|
| `-re` | 按真实时间产出（只对 lavfi / 文件输入） | 瞬间灌满，推流速度失控 |
| `-pix_fmt yuv420p` | 通用像素格式 | 很多播放器/浏览器黑屏 |
| `-c:v libx264` | H.264 编码 | 用 H.265 浏览器播不了 |
| `-preset ultrafast -tune zerolatency` | 实时编码、低延迟 | 延迟好几秒 |
| `-rtbufsize 100M` | 加大缓冲（屏幕捕获必加） | 报 `real-time buffer too full` |

> 真实摄像头（dshow）**不要加** `-re`；测试画面和文件输入**必须加**。

### 1.3 怎么确认推上去了

```powershell
# ① 媒体服务器里有没有这路流
scripts\zlm-streams.bat
#   或
Invoke-RestMethod "http://127.0.0.1/index/api/getMediaList?secret=<32位secret>"

# ② 平台怎么认（换成你的通道 id）
Invoke-RestMethod "http://127.0.0.1:8088/api/v1/channels/22/probe" -Headers @{ 'api-key'='vwg_console' }
#   期望：online=true、originName=推流、schemas=rtmp,rtsp,hls...

# ③ 平台页面
#   通道管理：该通道变「在线」
#   实时视频：出现卡片，点开即播
#   业务台账：多了一条 PUBLISH_START
```

### 1.4 本机推流的常见报错

| 现象 | 原因 | 处理 |
|---|---|---|
| `auth failed: stream not registered: live/xxx` | 平台没登记这条通道 / 已停用 | 先建通道并启用（见 0.3） |
| `Already publishing.` | 同一路流已经有发布者 | 停掉前一个推流进程；或换 stream id |
| `Connection refused` | ZLM 没起 / 端口不对 | `scripts\start-zlm.bat`，确认 1935 在监听 |
| 平台显示在线但播放黑屏 | 编码不是 H.264 / 没加 `-pix_fmt yuv420p` | 按 1.2 加参数重推 |
| 推流立刻退出、无报错 | 摄像头被别的程序占用 | 关掉相机/微信视频等再试 |

## 二、局域网其他设备推流

### 2.1 和本机推流的唯一区别：host 换成本机内网 IP

```
本机推      : rtmp://127.0.0.1/live/dev1
其他设备推  : rtmp://10.7.25.138/live/dev1      ← 10.7.25.138 = 本机内网 IP
```

### 2.2 推之前先做 30 秒连通性自检（在**对方设备**上执行）

```powershell
ping 10.7.25.138
Test-NetConnection 10.7.25.138 -Port 1935
```

| 结果 | 结论 | 下一步 |
|---|---|---|
| ping 通、1935 通 | ✅ 直接推 | 往下走 |
| ping 通、1935 不通 | 可能被防火墙挡，或 **Wi-Fi 开了 AP 隔离** | 见 2.5 |
| ping 不通 | 不同网段 / AP 隔离 / 不在同一 Wi-Fi | 见 2.5 |

### 2.3 各种设备怎么推

**A. 另一台 Windows 电脑（有 ffmpeg）**

```bat
ffmpeg -re -f lavfi -i "testsrc2=size=1280x720:rate=25" ^
  -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p ^
  -f flv rtmp://10.7.25.138/live/dev1
```

要推它的真实摄像头，把输入换成 `-f dshow -i "video=设备名"` 并去掉 `-re`。

**B. 手机（RTSP & RTMP Cam 这类 App）**

```
STREAMING MODE : RTMP Push
Server         : rtmp://10.7.25.138/live
Stream Key     : dev1
```

有的 App 只给一个输入框，就填完整地址 `rtmp://10.7.25.138/live/dev1`。

**C. 网络摄像头 / NVR**

后台找「RTMP 推流 / 自定义推流 / 平台接入」一栏，填 `rtmp://10.7.25.138/live/dev1`。
（不同厂商菜单名不同：海康「平台接入」、大华「RTMP」、宇视「第三方推流」）

**D. 树莓派 / Linux**

```bash
ffmpeg -f v4l2 -i /dev/video0 -c:v libx264 -preset ultrafast -tune zerolatency \
  -pix_fmt yuv420p -f flv rtmp://10.7.25.138/live/dev1
```

### 2.4 编码要求（对方设备上如果可选）

| 项 | 要求 | 备注 |
|---|---|---|
| 视频编码 | **H.264**（Baseline / Main / High 都行） | H.265/HEVC 浏览器播不了，会黑屏 |
| 分辨率/码率 | 720p + 2Mbps 起步就够 | 1080p 上行要 2~4Mbps |
| 音频 | AAC，可选 | 不需要可以关掉 |
| 协议/容器 | RTMP（FLV） | 填地址即确定 |

### 2.5 推不上来怎么查（按这个顺序）

1. **对方设备 ping 本机** —— 不通就是网络层问题（不同网段 / AP 隔离）
2. **对方设备测 1935 端口** —— 通不过但 ping 通 → 防火墙或端口没监听
   - 本机确认监听：`netstat -ano | findstr :1935` 应显示 `0.0.0.0:1935`
   - 本机确认防火墙：控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 → 勾上 `MediaServer` 和 `java`
3. **AP 隔离**（公司 Wi-Fi 最常见）：客户端之间禁止互访
   - 症状：ping 不通、端口测不通，但两台设备都能上网
   - 办法：**用手机开热点，让平台电脑和新设备都连这个热点**（同网段，一定能互访）
4. **平台侧检查**：通道是否已建且启用；`streamApp/streamId` 是否和推流地址完全一致（大小写、斜杠）
5. **看台账**：如果出现 `PUBLISH_REJECT`，说明流到了 ZLM 但被鉴权拒了 → 一定是通道没登记/已停用

### 2.6 对方推上来之后，平台会自动做什么

```
on_publish 放行 → 开流会话 → 通道 status=2（界面显示「在线」） → 设备在线 → 台账 PUBLISH_START
断流           → 结算会话时长 → 通道回离线 → 台账 PUBLISH_STOP
```

不需要在平台上点任何按钮。

## 三、本机去"拉"其他设备的流

### 3.1 什么时候需要拉流

设备**不会主动连你**，只提供一个 RTSP 地址（网络摄像头、NVR、别的流媒体服务器）——
这时不是"它推给我们"，而是**我们去拉它**。

> 方向性区别：**推流要求设备能到平台；拉流要求平台能到设备。**
> 所以手机/设备在别人家的网络里（NAT 后面）→ 拉不到，要反过来让它推。

### 3.2 操作四步

**① 建通道时选「拉流」并填地址**

```
通道管理 → 新增通道
  app / stream_id : live / pull1      ← 拉进来之后，本地流标识（自己起名）
  接入方式        : 拉流（平台主动拉）
  拉流地址        : rtsp://admin:pass@192.168.1.64:554/Streaming/Channels/101
```

**② 在通道列表点【发起拉流】**

平台会调媒体服务器的拉流代理（`addStreamProxy`），由 ZLM 去连源设备。

**③ 点【探测】确认**

```json
{ "online": true, "originType": 4, "originName": "拉流",
  "proxyRegistered": true, "conclusion": "拉流任务正常：流已上线" }
```

- `originType=4` = 这路流是**拉**进来的（1/2 = 推流）
- `proxyRegistered=true` 但 `online=false` = 任务下了但源没拉通（多半地址不通）

**④ 播放**：`实时视频` 页会出现这路流；或取地址

```powershell
Invoke-RestMethod "http://127.0.0.1:8088/api/v1/channels/18/play-address?protocol=flv" `
  -Headers @{ 'api-key'='vwg_console' }
# → http://10.7.25.138/live/pull1.live.flv
```

**停止拉流**：通道列表点【停止拉流】（对应 `delStreamProxy`），流随即注销、会话结算。

### 3.3 常见设备的 RTSP 地址格式

| 设备 | 地址格式 |
|---|---|
| 海康 IPC | `rtsp://admin:密码@IP:554/Streaming/Channels/101`（101=通道1主码流，102=子码流） |
| 大华 IPC | `rtsp://admin:密码@IP:554/cam/realmonitor?channel=1&subtype=0` |
| 宇视 | `rtsp://admin:密码@IP:554/media/video1` |
| ONVIF 通用 | 用 ONVIF 工具（如 ONVIF Device Manager）自动发现真实 RTSP 路径 |
| 手机 RTSP App | App 里直接显示，如 `rtsp://172.20.10.1:554/stream` |
| 别的流媒体服务器 | `rtsp://IP:554/live/<streamId>`（ZLM / mediamtx / SRS 都是这个形状） |

> 密码里含 `@ : /` 等字符时要做 URL 编码，否则地址解析会错。

### 3.4 拉不起来的排查顺序

| 现象（平台提示） | 原因 | 处理 |
|---|---|---|
| `3001 拉流失败：连不上拉流地址（play rtsp timeout）` | 源地址不通/设备离线/端口错 | 先在本机 `ffmpeg -rtsp_transport tcp -i "<地址>" -t 3 -f null -` 试播 |
| `3001 拉流失败：源设备拒绝认证` | 用户名密码错 | 核对地址里的账号口令 |
| `2003 该通道已在拉流中` | 重复发起 | 先【停止拉流】再发 |
| `3001 拉流失败：媒体服务器不支持这种源协议（not supported play schema）` | 源地址是 http/https，当前 ZLM 构建只接受 rtsp/rtmp 输入 | 换 rtsp:// 或 rtmp:// 源，或让媒体服务器编译对应协议 |
| `3001 拉流失败：媒体服务器拒绝了这次拉流` | 未归类的拒绝（原始报文在网关日志里搜 `addStreamProxy`） | 看日志原始 msg 定位，常见是源侧返回异常 |
| `2003 该通道当前没有进行中的拉流任务，无需停止` | 没任务可停 | 正常提示 |
| `2003 该通道当前是推流状态，不能同时发起拉流` | 同一路流标识已有推流 | 推/拉互斥，二选一 |
| `探测`显示 `proxyRegistered=true / online=false` | 任务在但源不通 | 检查源地址；确认后点【停止拉流】清理残留代理 |
| `5000 / 超时` | 媒体服务器响应慢 | 看平台日志；稍后重试 |

### 3.5 台帐里怎么区分推和拉

| 事件 | 谁写的 | 含义 |
|---|---|---|
| `STREAM_PULL_START` / `STREAM_PULL_STOP` | 平台（source=API/MANUAL） | **命令**下发/撤销 |
| `PUBLISH_START` / `PUBLISH_STOP` | ZLM 回调（source=ZLM） | 流**真的**上线/下线 |

两者分开记，是因为"我让你拉"和"拉到了"是两件事。

## 四、推 vs 拉 一张表记住

| | 推流 Push | 拉流 Pull |
|---|---|---|
| 谁发起连接 | 设备/主机 → 平台 | 平台 → 设备 |
| 地址举例 | `rtmp://10.7.25.138/live/dev1` | `rtsp://admin:pass@192.168.1.64:554/...` |
| 平台侧操作 | 建通道即可（等设备推） | 建通道 + 填拉流地址 + 点【发起拉流】 |
| 对 NAT 友好吗 | ✅ 友好（出站） | ❌ 不友好（入站） |
| 典型设备 | USB 摄像头+主机、编码器、手机、NVR | IPC、NVR、其它流媒体服务器 |
| 上线回调 | `on_publish` → `on_stream_changed` | **只有** `on_stream_changed` |
| 排查入口 | 检查通道登记 + 网络 1935 | 【探测】按钮 / ffmpeg 直连源地址 |

## 六、FAQ

**Q1：一定要改 `vgw.zlm.base-url` 吗？**
本机看不用改。要让**别的电脑/手机**播放平台签发的地址，才需要改成 `http://10.7.25.138`，否则对方拿到的是 `127.0.0.1`（他自己）。

**Q2：为什么要先建通道？能不能先推再建？**
不行。`on_publish` 是同步闸门，未登记的流会被直接拒绝并断开，台账记 `PUBLISH_REJECT`。

**Q3：同一路流能两台设备同时推吗？**
不能。一个 `app/stream` 同时只能有一个发布者（第二个报 `Already publishing`）。不同 `streamId` 可以并行推任意多路。

**Q4：一个设备有多路流怎么办？**
一台设备建多条通道（主码流/子码流、屏幕/摄像头），各自 `streamId`，各自推流即可。

**Q5：别的设备要"看"平台上的流，怎么给地址？**
给它 `GET /api/v1/channels/{id}/play-address?protocol=flv` 返回的 URL（并确保 host 是内网 IP、带 api-key 才能自己调接口）。

**Q6：手机能既当源又当播放器吗？**
可以。手机当源（RTSP 服务端或 RTMP 推流），它也能用浏览器打开平台的实时视频页看。

**Q7：能不能不装 ffmpeg？**
能。用 `http://<host>/player.html` 播放；推流则可以用手机 App、IPC 自带推流、OBS 等。

**Q8：拉流和推流能共存吗？**
同一**通道**互斥（会报 `不能同时发起拉流`），不同通道当然可以同时有推有拉。

**Q9：为什么 ZLM 里能看到流，平台里却没有？**
说明这路流没在平台登记（`live/fakesrc` 这种被删过通道的流就是例子）。要么重建通道，要么停掉推流。

**Q10：演示时怎么最稳？**
源用 `push-test.bat`（彩条，永远不依赖硬件/网络），拉流用本机假流或 mediamtx，别用手机热点当关键环节。
