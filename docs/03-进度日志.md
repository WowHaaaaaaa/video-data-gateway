### 今天踩的坑（重要，都解决了）

1. **HTTPS 只能 node 走通**，curl 走 Schannel 全部 000 → 所有下载改用 node 脚本
2. **ZLM config.ini 带 BOM 会被忽略**，导致整套默认配置回写
3. **ZLM secret 必须是 32 位字母数字串**，UUID 格式非法会被随机替换
4. **mysqld 处理不了中文路径**（路径被截断成 `C:\Users\data\`）→ 用 ASCII 临时目录 junction 绕过
5. **3306 上有公司预装的 MySQL267 服务** → 我们改用 3307
6. **on_stream_changed 按协议重复触发** → ZLM 侧限 rtmp + 代码侧"原子更新会话状态"去重（并发竞态）
7. **.bat 里写中文会崩**（cmd 按 GBK 解析 UTF-8）→ bat 只做 ASCII 薄壳，逻辑放 .ps1
8. **ZLM 的 startRecord/stopRecord 必须显式传 vhost**（`__defaultVhost__`），否则报"Required parameter missed"
9. **ZLM 在 Windows 下按 GBK 输出回调 JSON**，`file_path` 里的中文目录会变成乱码（`ʓƵʽޝ͸٘`）
   → 改用回调里的相对路径字段 `url`（纯 ASCII）拼成 `http://host/record/...` 存库，顺带能直接回放

### 联调 Polishing（Apifox 接入时暴露的三处问题）

1. **分页参数在文档里"消失"**：`PageQuery` 是 POJO，没加 `@ParameterObject` 时 springdoc 会把它
   渲染成一个名为 `query` 的必填对象参数（文档上看不到 page/size，Apifox 里不知道填什么）。
   6 个分页接口全部加上 `@ParameterObject`，并给 `PageQuery` 补 `@Schema` 说明/示例。
2. **`$.data.pullUrl 不允许为 null`**：服务端返回 `"pullUrl": null`，而 OpenAPI 3.0 的 schema 里
   该属性是 `{"type":"string"}` 且未声明 `nullable:true` —— 按规范 null 就是"不符合定义"，
   Apifox 的「校验响应」据此报红。这不是运行期 bug，但契约确实不精确。
   解法：`spring.jackson.default-property-inclusion: non_null`，没值的字段直接不输出
   （非必填属性缺席是合法的），一次修掉全部同类告警，响应也更小。
3. **表格空白**：Element Plus 的 `fit=true` 会把剩余宽度全塞给弹性列 → 改用 `:fit="false"`。

### 完成内容

**通道级隔离（谁能看哪一路）**
- `biz_api_client.allowed_channels`（逗号分隔通道 ID，NULL=不限）落地到接口层：新增 `PUT/POST /api-clients/{id}/channels` 配置接口，创建客户端时也可直接指定
- 新增 `common/AccessScope`（静态工具，读 ThreadLocal 里的当前客户端）+ `service/ChannelAccessService`（统一越权判定 + 台账留痕），避免每个接口各写一遍
- 查询类接口全部按授权通道过滤：`/channels`、`/streams`、`/ledger`、`/sessions`、`/recordings`
- 动作类接口全部先鉴权：播放地址、录像开关、通道改删、拉流/停止拉流、录像文件清理
- 越权一律 401 + 记一条 `API_CALL`（resultCode=2003），审计可追溯
- 前端「API 客户端」页：新增「可访问通道」列 + 创建时可选「全部通道/指定通道」+ 行内【通道授权】弹窗；
  表格紧凑化（收窄各列、去掉「创建时间」列、「重置密钥/删除」收进「更多」菜单）；
  通道下拉显示「通道名（编码）· app/stream」，避免只看通道名对不上流标识；
  列宽重排（踩了两轮）：Element Plus 默认 `fit=true` 时，会把**表格比列宽之和多出来的宽度**分给
  「没有写 width 的弹性列」（按 min-width 比例）。只给一列设 min-width → 那一列独吞所有余量
  （「客户端名称」被撑到 340px，看起来就是"名称和联系人之间一大片空白"）；
  给四列都设 min-width → 余量还是按比例落在前几列，窗口一宽照样空。
  最终改成 **`:fit="false"`**：列宽就是设定值，表格不再被拉伸，多余宽度留在容器右侧（不再插在列与列之间）。
  同时「重置密钥 / 删除」从「更多」下拉里还原成平铺按钮，操作一屏可见；通道表与设备表只做收窄，避免横向滚动条

**平台发起拉流（把网络摄像头接进来）**
- `ZlmApiClient` 新增 `addStreamProxy` / `delStreamProxy` / `originTypeOf`
- 新增 `service/StreamPullService` + `POST /channels/{id}/pull`、`/channels/{id}/unpull`
- 校验：地址协议白名单、通道停用、未配地址、正在推流（互斥）、重复发起、无任务可停；台账里地址脱敏为 `rtsp://user:***@...`
- 新增台账事件 `STREAM_PULL_START` / `STREAM_PULL_STOP`（命令层），与 ZLM 的 `PUBLISH_START/STOP`（状态层）分开记

- `/streams` 增加 `originType / originName / pulled`；状态对账从「只认 originType==1」改为「认所有源类型」
- 前端「通道管理」页：新增「接入」列（推流/拉流）+ 行内【发起拉流】【停止拉流】按钮 + 拉流地址填写提示；
  流标识旁新增【探测】按钮，弹窗直接展示媒体服务器上的真实状态与一句人话结论；

### 今天踩的坑

1. **MyBatis-Plus 的 `.in()` 传空集合会拼出 `IN ()`**，直接 SQL 语法错误。
   解法：受限但一个通道都没授权时返回哨兵 `[-1]`，语义正好是"全拒"且 SQL 合法。
2. **拉流代理不会触发 `on_publish`**，只有 `on_stream_changed`。
   若沿用"regist=true 直接 return"的老逻辑，拉流会出现"流在跑、但没有会话、通道还是离线"的鬼状态。
   解法：regist=true 时先查有没有进行中会话，没有才补开户（推流路径不会重复记账）。
3. **ZLM mediaList 里转协议产物的 originType 会继承源类型**（推流时 5 条 schema 全是 1）。
   所以"是否在线"不能只判断 `==1`（否则拉流永远显示离线），改为判断"是否为源类型"。
4. **内网没有可拉流的 RTSP 设备**（扫描 10.7.25.0/24 的 554/8554 及常见摄像头端口，只有网关、同事电脑、手机）。
   演示改用回环方案：`scripts\push-test.bat src1` 制造一路源流，再把它自己的 RTSP 地址当设备地址拉进另一路通道；
   换真实 IPC 时只改「拉流地址」一个字段，代码零改动。
5. **Element Plus 2.6+ 的 radio 用 `value` 而不是 `label`** 承载取值，写错会导致选项值变成显示文案。
6. **`addStreamProxy` 报 `This stream already exists`**：ZLM 的 `retry_count` 默认 -1（无限重试），
   第一次拉不通时代理会留在媒体服务器上反复重连、而流始终不注册 —— `getMediaList` 里看不到它，
   界面上通道还是"离线"，再点一次就报"已存在"。
   修复三件套：显式 `retry_count=3` + `timeout_sec=5` 断根；下发前 `getProxyInfo` 清残留兜底；
   新增 `GET /channels/{id}/probe`（界面【探测】按钮）把媒体服务器上的真实状态摊开。
   顺带把 ZLM 的英文报错（already exists / play rtsp timeout / 401）翻译成能指导操作的中文。
7. **读超时 ≠ 媒体服务器不可达**：下发拉流时 ZLM 会阻塞地连源地址，我们 10s 读超时先回来了，
   但代理可能已注册成功。所以超时后先查代理：在 → 按"已下发未上线"处理；不在 → 才报失败。
